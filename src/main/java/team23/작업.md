# QCheck Backend - 완료된 기능 정리

## Auth `/auth`

인증 불필요 (전역 인터셉터 제외 대상)

| 메서드 | 경로 | 설명 |
|--------|------|------|
| GET | `/auth/login` | Discord OAuth2 로그인 페이지로 리다이렉트 |
| GET | `/auth/code?code=` | Discord 인가코드 콜백. 기존 회원이면 access token 반환 + refresh token 쿠키 설정, 신규 회원이면 10분짜리 signup JWT 반환 |
| GET | `/auth/username/check?username=` | 아이디 중복 확인 |
| POST | `/auth/signup` | 회원가입. `Authorization: Bearer <signup JWT>` 헤더 필요. 성공 시 access token 반환 + refresh token 쿠키 설정 |
| POST | `/auth/refresh` | `refresh_token` 쿠키로 access/refresh token 재발급 |

## 인증 방식

- **JWT Bearer**: `Authorization: Bearer <access token>` — 프로덕션
- **X-USER-ID 헤더**: 개발용 fallback (JWT Bearer가 없을 때만 사용)
- **refresh token**: `refresh_token` HTTP-only 쿠키

## 전역 JWT 인증 (`JwtAuthInterceptor`)

`/auth/**`, `/swagger-ui/**`, `/v3/api-docs/**`를 제외한 **모든 요청**에 대해 `HandlerInterceptor`로 토큰을 검사한다.

검사 순서:
1. `Authorization: Bearer <token>` 헤더가 있으면 `JwtService.extractUserId()`로 access token 유효성 검사
2. 없으면 `X-USER-ID` 헤더(개발용) 확인
3. 둘 다 없거나 유효하지 않으면 `ApiResponse` 형식의 401 JSON 응답 반환

> `GlobalExceptionHandler`는 인터셉터 단계의 예외를 처리하지 못하므로,  
> 인터셉터 내에서 `ObjectMapper`를 직접 사용해 응답을 직렬화한다.

## 역할 체계 (ClubRole)

| 역할 | 권한 |
|------|------|
| OWNER | 모든 권한 |
| ADMIN | 이벤트 생성/수정, 멤버 관리 (OWNER 역할 부여 불가) |
| MEMBER | 이벤트 조회 및 등록 |

## 등록 상태 (RegistrationStatus)

`REGISTERED` → `CHECKED_IN` / `CANCELED`
