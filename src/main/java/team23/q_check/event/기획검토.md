# 일정관리 기획 검토 사항

## 1. 월별 일정 조회 — "내가 참가하고 있는 동아리" 기준

**질문:** "참가하고 있는 동아리"를 어떤 기준으로 판단하나요?

- **A안 (현재 구현):** `ClubMember` 테이블 기준 — 동아리 멤버이면 해당 동아리의 모든 행사가 캘린더에 표시됨
- **B안:** `Registration` 테이블 기준 — 사용자가 직접 신청한 행사만 캘린더에 표시됨

현재는 A안으로 구현했습니다. 동아리 멤버라면 행사 신청 여부와 무관하게 동아리 일정을 볼 수 있어야 한다고 판단했습니다.

---

## 2. 검색/필터에서 CANCELED 등록 처리

**질문:** 참가 신청을 취소(`CANCELED`)한 행사도 검색/필터 결과에 포함해야 하나요?

현재 구현에서는 `REGISTERED`, `CHECKED_IN` 상태인 행사만 검색/필터 대상으로 포함합니다. `CANCELED`는 제외했습니다.

---

## 3. 필터링 — 조건 중복 적용

**질문:** 일정관리.md의 3번 "기간, 이름, 동아리 중 하나 선택"이라고 되어 있는데, 여러 조건을 동시에 적용할 수 있어야 하나요?

예) `startDate + endDate + clubName` 동시 사용 가능 여부

현재 구현에서는 여러 조건을 동시에 AND로 조합할 수 있도록 구현했습니다. 하나만 허용해야 한다면 상호 배타 검증 로직을 추가해야 합니다.

---

## 4. 필터 — 기간(startDate, endDate) 파라미터 형식

**질문:** 기간 필터에서 날짜만(LocalDate) 받아야 하나요, 아니면 날짜+시간(LocalDateTime)으로 받아야 하나요?

현재 구현은 ISO-8601 datetime 형식(`2024-03-01T00:00:00`)으로 받습니다. 날짜만 입력받는 경우 프론트에서 `T00:00:00` / `T23:59:59`를 붙여서 보내는 방식으로 사용 가능합니다.

---

## 5. 월별 조회 — 행사 날짜 기준

**질문:** 행사의 `startTime`이 해당 월에 속하는 행사만 반환하면 되나요? 아니면 `startTime`~`endTime` 범위가 해당 월에 걸치는 행사도 포함해야 하나요?

현재 구현에서는 `startTime`이 해당 연월인 행사만 반환합니다. `Event` 엔티티에 `endTime`이 있으나, 현재 행사 생성 시 `endTime = startTime`으로 저장되고 있어 실질적 차이가 없습니다.
